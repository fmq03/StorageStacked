# AXI2FLIT 验证

## 1. 验证环境与入口

测试使用 C++17、SystemC 和 2ns AXI 时钟。默认数据宽度 256 位，回归覆盖 256/512/1024 位。链路依赖和路径设置见[接入说明](../integration/README.md)。

本页描述现有测试的覆盖与判据，端口契约见[SoC 接口表](../../doc/SoC侧接口对接表.md)和[存储接口表](../../doc/存储侧接口对接表.md)。现有全链路命令固定使用 BFM 与简单内存，不能据此声称尚未接入的主机和存储模型已完成验收。

在项目根目录执行：

```bash
make preflight
make full-link-all
make full-link-negative
make -C systemc report
```

`preflight` 包含桥功能、消息黄金向量、帧格式、边界、适配器、链路单元、参数化和桥性能回归。`full-link-all` 单独运行实际 UcieLink 与存储的联合测试。命令以非零退出码表示失败；单个用例通过不能代替最终汇总。

## 2. 套件与覆盖

| 入口 | 测试文件 | 范围与判据 |
|---|---|---|
| `test-all` | `tb_axi2flit.cpp` | 三种位宽；初始credit、RP 路由、读写响应、双向背压、续传和同 ID 顺序检查 |
| `golden-all` | `tb_golden_vectors.cpp` | 每位宽 71 项；固定消息黄金字节，覆盖请求、数据、响应、credit及字段宽度 |
| `wire-all` | `tb_aou_wire.cpp` | 三种位宽；PH 黄金字节、48 个起点位、16 个credit位、FDId、物理映射、续传及非法编码 |
| `boundary-all` | `tb_preintegration.cpp` | 三位宽 × RP1/2/4；协调本地复位、96 条读请求随机背压、credit事件拥塞；每位宽 12 个非法 AXI 场景 |
| `adapter` | `tb_ucie_adapter.cpp` | 250 字节长度、全部 2048 个物理位单错、深度 1 双向 FIFO、训练门控和握手时间 |
| `ucie-unit` | 链路依赖的单元测试 | 编译链路主程序并运行 22 项独立单元检查 |
| `config-check` | 适配器及边界测试 | x8、PAM4、48GB/s、TAT=80ns；参数匹配与桥功能 |
| `perf-all` | `tb_axi2flit_perf.cpp` | 简化链路下的吞吐、载荷效率、延迟及credit环路预算 |
| `full-link-all` | `tb_full_link.cpp` | 12 种配置，每配置 12 组用例，实际字节存储、错误重放和事务守恒 |
| `full-link-negative` | `tb_full_link.cpp` | 破坏一处记分板期望，必须检出读数据不匹配且退出码为 1 |

消息黄金向量直接使用固定期望值，未通过被测编码器生成。它们只检查项目消息格式；PH 和物理帧映射由独立套件检查。帧解析回归还覆盖七类消息的全部 48 个起点、4096 条固定种子混合消息、空粒度、纯credit帧、保留编码和重叠起点。

桥功能测试的出站帧由测试侧独立扫描器解析，入站由桥流解析器处理。反序列化将 `used_granules` 设为 -1，确保解析不依赖发送侧辅助信息。边界测试在 RP=4 时发送一帧 80 条credit事件，检查它超过 64 项内部事件 FIFO 深度后仍能排空，并继续接受后续帧。

非法 AXI 场景分别检查 AW/AR 的 FIXED、WRAP、超 SIZE、未对齐和跨 4KB，以及 WLAST 提前或缺失。负向测试必须捕获指定诊断，任意崩溃或超时不计为通过。

## 3. 全链路功能验证

### 配置

无误码配置为三种位宽分别运行 RP1、RP2、RP4，共 9 种；另外每位宽运行 RP2 压力与重放组合，共 3 种。`--stress` 将四个公开帧 FIFO 和两个存储 FIFO 的深度设为 1，重试缓冲设为 8，反馈延迟设为 256 UI，内存固定访问时间设为 80ns，并施加随机响应背压。`--replay` 使用种子 7 注入 2% 的额外帧错误。

### 用例

| 用例 | 内容 |
|---|---|
| TC1 | 零初始化单拍读 |
| TC2 | 单拍写后读，逐字节检查数据、ID、USER、响应和 LAST |
| TC3 | 2/4/16 拍及全宽 4KB 最大突发 |
| TC4 | 部分选通和全零选通覆盖写 |
| TC5 | 4 字节窄突发、字节通道轮转及全宽读回 |
| TC6 | 256 拍 × 4 字节长突发，数据总量超过写数据credit窗口 |
| TC7 | 恰好结束在 4KB 边界的合法读写 |
| TC8 | 越界与地址高位检查，错误访问不得破坏有效地址数据 |
| TC9 | 多 AW 排队、读写重叠、多 ID 和多 RP |
| TC10 | 同方向、同 ID 的响应顺序 |
| TC11 | 长时间 B/R 背压、credit耗尽和恢复 |
| TC12 | 固定种子的突发长度、字节选通和发送间隔组合 |

256 位全宽突发受 4KB 限制最多 128 拍，512/1024 位分别最多 64/32 拍。256 拍测试采用每拍 4 字节的窄访问。各 RP 共享同一个地址窗口。

### 检查方法

记分板仅观察 SoC 侧实际 AXI 握手，以独立字节地址表维护期望内容；根据 AW/W 建立写期望，根据 AR 建立逐拍读期望。它不读取被测内存，不用桥的编解码器生成期望数据。测试通过等待写响应来建立相同地址的写后读依赖。

五通道均检查背压期间数据稳定，核对 W/R 拍数、WLAST/RLAST、B/R ID、USER、RESP 及完整数据。结束时对账 AXI、响应端和内存事务数，检查背压、响应credit耗尽、多笔未完成事务等覆盖；排空后继续观察静默期以检测迟到重复响应。全局仿真上限为 2ms。

无误码场景必须没有 CRC 错误；重放场景必须实际发生 CRC 错误和重发，最终 AXI 数据仍须全部正确。256 位读数据每条占 8 粒度，可整除 48 粒度载荷区，不强制其发生响应续传；512/1024 位须观察到响应跨帧。

成功日志包含：

```text
FULL_LINK: 12 cases / 0 errors
ALL FULL-LINK TESTS PASSED
```

运行矩阵合计 144 组配置内用例，每配置 55 笔写、66 笔读。默认 256 位 RP1 的握手计数为 AW=55、W=1219、B=55、AR=66、R=1241。最终结果以本次生成的日志和命令退出码为准。

## 4. 桥性能测量

### 模型与统计口径

`perf-all` 和 `report` 使用 `LinkPacer + FlitDelayLine + RemoteAouModel`。对端返回由 ID 和拍号生成的数据图样，检查写数据，但不保存可写后读的实际内存。该环境测量桥性能基线，未实例化 UcieLink。

`LinkPacer` 将 48B/ns 转换为平均每 5.333ns 一帧的传输预算；空闲后首帧可直接使用积攒预算。飞行延迟由单独的队列模拟，不能把帧间隔当作空载飞行时间。

持续吞吐测量使用 RP1、16 拍突发、最多 64 笔未完成突发，预热 600 拍、统计 2000 拍。PERF-1/2 分别测持续读/写，PERF-3 测空载单事务延迟，PERF-4 测混合读写；这些场景单向飞行延迟为零。PERF-5 现场重测零延迟对照，再加入双向各 20ns 的飞行延迟，核对往返增量和读吞吐保持率。

| 指标 | 定义 |
|---|---|
| AXI 吞吐 | 统计窗口内被接受的有效数据字节 / 窗口时间 |
| 效率 A | 应用字节 / 数据方向帧数 / 256B |
| 效率 B | 应用字节 / 数据方向帧数 / 240B |
| 效率 C | 应用字节 / 双向业务消息折算的裸链路字节 |
| 读 TX / RX 延迟 | ARVALID 至请求帧发送 / 返回帧到达至 RVALID |
| 写 TX / RX 延迟 | WLAST 至对应帧发送 / 返回帧到达至 BVALID |

A、B 使用数据所在方向的帧数，C 汇总双向业务粒度；窗口边界处完整消息与帧的统计时刻可能不同。混合流量应分别报告两个方向。所有效率必须注明分母，B 不能当作整个 256 字节帧的效率。

### 回归门限

| 数据宽度 | 读吞吐 GB/s | 写吞吐 GB/s | 效率 B | TX 延迟 | RX 延迟 |
|---:|---:|---:|---:|---:|---:|
| 256 | ≥15.80 | ≥15.80 | 不设门限 | ≤12ns | ≤8ns |
| 512 | ≥31.50 | ≥31.50 | 不设门限 | ≤12ns | ≤8ns |
| 1024 | ≥42.00 | ≥41.50 | ≥93% | ≤12ns | ≤8ns |

PERF-5 还要求往返增量与配置 TAT 的偏差不超过 2ns、读吞吐保持率不低于 95%。门限由 `AXI_DATA_WIDTH_CFG` 选择，任一检查失败均返回非零。

默认配置的桥基线参考读/写吞吐分别为 256 位 16.00/16.00GB/s、512 位 32.00/32.00GB/s、1024 位 42.66/42.40GB/s。1024 位参考效率 B 为 94.79%/94.22%，效率 A 为 88.87%/88.33%，对应这里定义的桥回归门限。是否通过以本次报告和退出码为准；数据图样、请求字段和定界错误也必须为零。

256/512 位在 2ns 时钟下的 AXI 输入上限分别为 16/32GB/s，低于链路裸带宽；这两种配置不按 B 设置效率门限。容量预算和消息粒度见[设计文档](design.md)。

### 与全链路性能的关系

`full-link-all` 验证实际链路和实际字节存储的事务闭环，包含主动等待与长背压，不提供稳态带宽验收。其 CSV 可计算端到端事务延迟，包含适配器、链路、响应端和存储时间；这与桥内 TX/RX 延迟是不同量。

默认简单内存串行服务，1024 位、16 拍突发的纯服务吞吐上限为 `2048B / (20ns + 16×2ns) ≈ 39.38GB/s`，还未计入链路和排队开销。因此桥基线通过不意味着该存储配置的全链路可达到 42GB/s。联合性能测量需要专门的持续负载、预热窗口和足够的后端服务能力。

## 5. 产物与波形判读

`systemc/sim/perf_report.txt` 保存桥性能汇总。全链路每个配置生成独立的 `full_link_<位宽>_rp<数量>[_stress][_replay].csv/.vcd`；`full-link-all` 同时保存 `.log`。

```bash
make full-link-wave
make WIDTH=1024 FULL_LINK_VCD=sim/full_link_1024_rp2_stress_replay.vcd full-link-wave
gtkwave systemc/sim/full_link_256_rp1.vcd
```

波形页面读取已有 VCD，支持用例切换、缩放和平移。总线数据保留为十六进制字符串，可查看完整 64 位地址和 1024 位数据。

先检查 TC2 的 AW、W、B、AR、R 各一次握手，数据读回一致；再检查 TC3 的拍数为 LEN+1，仅末拍 LAST=1；TC11 中 VALID=1、READY=0 时完整数据须保持不变。计数以时钟上升沿的 VALID 与 READY 同时为 1 为准，不能按电平持续时间计数。

CSV 只记录握手事件，数据字符串最右侧对应字节通道 0。W 行地址为原 AW 突发首地址，R 行地址由已接受 AR 和拍号推导，B 行地址为 0；这些地址不是额外的 W/B/R 引脚。重复 ID 按对应方向的在途队列匹配，不能当作全局唯一编号。具体命令和信号分组见[全链路使用说明](../../doc/UCIe全链路仿真计划与使用.md)。

## 6. 验证边界

固定种子和有限配置回归能够检查列出的功能及性能门限，不覆盖全部并发交错。未覆盖多种子长时间运行、运行期间链路热复位、真实 DRAM 时序、RTL 时序和独占/原子执行。简单内存的 LOCK 和非法选通错误路径没有专门的全链路测试用例；不能仅凭整体通过声称每条错误路径都已验证。

链路组件的逐位 CRC 测试检查本模型的 CRC16-CCITT 算法与覆盖范围。不同主机、后端、链路参数和突发负载接入后，仍需在相应配置下重新运行功能与性能验证。

## 7. 新主机和存储模型的交接验收

| 接入对象 | 必须补充的检查 | 不能直接沿用的假设 |
|---|---|---|
| 主机/trace 回放器 | 独立握手、AW/W 顺序、合法 burst、ID/属性映射、读数据提取、完成后释放上下文 | 文件时间等于接受时间；一个主机请求等于一个 AXI beat |
| 新存储后端 | 完整请求与响应长度、lane/掩码、同组顺序、读写数据可见性、错误通知 | 后端请求入队等于写完成；AXI ID 唯一；一个后端请求等于一拍 |
| 有限并发适配器 | 拒绝后重试不重复、异步数据有效期、乱序聚合、响应 FIFO 满时保留结果 | 无限队列不会改变性能；同 ID 仅排序响应即可保证全部数据依赖 |
| 联合顶层 | 位宽/地址/时间一致、单一信号驱动、初始化正确、全部在途访问和链路反馈排空 | CPU 停止或 Target 空闲就代表整个系统完成 |

先分别运行“新主机＋简单内存”和“原 BFM＋新后端”，再连接两端。已有 BFM 的窗口、初值和简单内存专用计数应按新配置调整；它不能不加修改地证明任意程序的数据语义。真实主机没有覆盖的长 burst、窄访问、错误和背压场景由合成测试补齐。

验收记录应包含提交号、构建参数、运行配置、最终日志、AXI VCD/CSV、独立数据检查及退出码。各层编号、时间和计数的关联方式见[联仿交接约定](../../doc/全链路联合仿真接入指南.md#11-联仿交接约定)。本节是新增模型的验收要求，当前不存在自动运行这些新模型的 make 目标。
