# AXI 存储项目：从输入到读回结果

这个项目处理存储读写。例如，把数字 41 写到一个地址，再从同一地址读出来，
就能检查数据是否真的走过 AXI、UCIe 和内存模型。第一次使用先做这个小实验。

| 想做什么 | 从哪里开始 |
|---|---|

| 查询 JSON 的全部字段、五通道端口和数据排列 | [输入说明](INPUTS.md) |
| 阅读实际返回值、波形和检查结果 | [输出说明](OUTPUTS.md) |
| 理解固定六笔 SMOKE，或给项目增加专项检查 | [从零添加 SMOKE](03-从零添加SMOKE测试.md) |

## 先分清三个项目

本项目用 `examples/*.json` 放独立读写的输入，没有 `user/` 目录。
CoralNPU 和 Vortex 的 `user/` 放的是计算程序。程序运行时会发起读写，
它们直接连接本项目的 AXI 信号接口。

`--input` 后面填 JSON 文件路径，文件里按顺序写明要读或写哪个地址。
如果你已有设备发出的 AXI 信号，按 [接口说明](../INTERFACE.md) 连接 SystemC 端口。

## 阅读时的几个约定

- 命令前会写明所在目录；`results/` 是 AXI 独立入口的结果目录。
- “预期”表示根据输入和源码应得到什么；实际是否通过，要打开自己这次运行的 `summary.json`。
- [输出说明](OUTPUTS.md) 中 2026-09-25 的结果是历史运行记录，保留供比较。
- 本轮文档完善核对当前源码、配置和入口；文档检查与重新执行硬件仿真分开记录。
