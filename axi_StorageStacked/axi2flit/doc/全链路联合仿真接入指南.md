# 独立 AXI 存储链路接入

公开边界是 `storage_axi::AouBackend` 的 AXI256 五通道，参见
[根目录接口契约](../../INTERFACE.md) 和 [构建/输入输出说明](../../README.md)。
本项目不包含处理器。gem5+Vortex 与 CoralNPU 分别位于独立驱动仓库。

```text
外部 AXI master ⇄ AouBackend ⇄ Axi2Flit ⇄ UcieAouAdapter
  ⇄ 双向 UcieLink ⇄ AouTarget ⇄ MemSimBackend ⇄ 在线 mem_sim
```

| 根目录下的文件 | 职责 |
|---|---|
| `storage_axi/axi_signals.hh` | 公开 AXI 信号、master/slave 端口 |
| `storage_axi/storage_config.hh` | 不含处理器状态的存储配置 |
| `storage_axi/aou_backend.cc` | AXI 信号接收、AXI2Flit、UCIe 与存储端拓扑 |
| `storage_axi/memsim_backend.cc` | burst 拆分、有界排队、内存步进与真实数据返回 |
| `mem_sim/integration/online.h/.cpp` | 无 SystemC 依赖的在线内存 C ABI |
| `examples/axi_storage.cc` | 独立文件输入到 AXI master、响应输出 |
| `scripts/run.py` | 输入校验、独立字节模型和全链路证据验收 |

独立构建入口为 `./run.sh build`；读写为
`./run.sh run --input examples/roundtrip.json --output results/my-run`；完整验收为 `./run.sh test`。
每次使用新结果目录。不得用启动、退出码或产物存在替代数据、波形和在线内存验收。

两个驱动用 `STORAGE_STACK_ROOT` 选择公共源码目录：

- [gem5+Vortex 驱动](https://github.com/hy2581/vortex_StorageStacked)：其 TLM master 生成 AXI；公共源文件由 SCons 编译到 gem5 自带的 SystemC 中。
- [CoralNPU 驱动](https://github.com/hy2581/coralnpu_StorageStacked)：其原生异步适配器生成 AXI；通过 CMake 链接公共库与独立 SystemC。

同一进程只能有一套 SystemC；时间分辨率统一 1 fs。两驱动各有独立构建产物和内存状态。
内存完成必须沿 UCIe 和 AXI 的 B/R 返回，不能由私有 DDR、functional 访问或 trace 回放替代。

结果保留 AXI VCD/五通道 CSV、两端 Flit、在线内存请求/返回、DRAM 命令、DFI 和最终镜像。
公共检查器从原始波形与 Flit 独立恢复字节；处理器计算正确性由各驱动的验收器另行核对。
PHY/DFI 为行为模型；简单存储 BFM 只用于底层组件测试，不属于生产访存链路。
实际执行证据见 [ACCEPTANCE.md](../../ACCEPTANCE.md)。
