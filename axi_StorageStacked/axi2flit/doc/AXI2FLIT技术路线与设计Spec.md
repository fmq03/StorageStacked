# AXI2FLIT 架构与实现范围

项目围绕 AXI 请求到远端存储的完整访问路径构建 SystemC 行为仿真环境。SoC 侧使用五通道 AXI 信号，存储侧使用整笔突发请求/响应 FIFO；中间完成消息编码、 credit 管理、帧传输和响应恢复。

本页概述已实现的架构。主机接入以 [SoC 接口表](SoC侧接口对接表.md)为准，存储接入以[存储接口表第 1～3 节](存储侧接口对接表.md)为准；主机适配器、后端包装层和精简接口的设计方案不表示它们已经存在于代码中。

## 模块边界

| 层次 | 实现 | 主要职责 |
|---|---|---|
| 主机入口 | `Axi2Flit` | AW/W/AR 接收，B/R 返回，合法请求检查与 ID 顺序跟踪 |
| 消息发送 | `MsgBuilder`、`FlitPacker` | 字段编码、 credit 检查、多消息装帧和跨帧续传 |
| 消息接收 | `AouStreamDecoder`、`FlitUnpacker`、`MsgDecoder` | 定界、重组、 credit 分流和响应解码 |
| 链路适配 | `UcieAouAdapter` | 帧信号与 FDI FIFO 转换及训练状态门控 |
| 双向链路 | `UcieLink` | 物理帧传输、CRC、确认反馈和错误重放 |
| 存储响应 | `AouTarget` | 解包请求、组装突发、访问后端和打包响应 |
| 存储后端 | `SimpleBurstMemory` | 按地址读写真实字节数据，处理选通和访问延迟 |

## 数据与时序

桥支持 256/512/1024 位数据、64 位地址、10 位 ID 和 16 位 USER。请求限于按 SIZE 对齐且不跨 4KB 的 INCR 突发。AXI 逐拍握手，帧使用有效/就绪或 FIFO 接受语义，存储请求和响应对象各携带一个完整突发。接口允许多笔在途请求，是否并行服务由后端决定；当前简单内存串行处理。

逻辑传输内容为 250 字节，由 10 字节帧头和 240 字节载荷组成；载荷划分为 48 个 5 字节粒度。消息 credit 按资源平面和类型分别管理，跨帧重组仅使用传输字节中的消息起点和首字节。具体位域由[字节格式与接口](../systemc/doc/wire_contract.md)定义。

默认桥时钟为 2ns，链路聚合裸带宽为 48GB/s，简单内存按 `20ns + 2ns × 拍数` 串行服务。三者使用同一 SystemC 时间轴，分别保留接口周期、链路事件和存储事务粒度。

## 验证组织

桥功能、黄金字节向量、帧解析、接口边界、链路适配组件及桥性能由 `make preflight` 汇总。实际 UcieLink、响应端和字节存储由 `make full-link-all` 验证，覆盖三种位宽及多资源平面、长突发、背压和错误重放。

桥性能基线使用节流与飞行延迟模型，并以模式数据响应器供数。全链路功能结果与桥性能结果分别报告，完整链路的持续吞吐需要独立负载与统计窗口。
