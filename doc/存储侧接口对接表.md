# 存储侧接口对接表

本文用于链路与外部存储模型的字段对齐。第 1～3 节列出当前已实现接口；第 4～6 节提出面向普通读写存储模型的精简接口和适配规则。精简接口及 `MemoryAdapter` 尚未实现，当前代码仍使用 `SimpleMemRequest/Response`。

定义见 [simple_mem_if.h](../systemc/include/simple_mem_if.h)、[axi_if.h](../systemc/include/axi_if.h)，消费规则见 [aou_target.h](../systemc/integration/aou_target.h)。表中“链路”指存储侧响应端 `AouTarget`，数据宽度记为 `D = AXI_DATA_BYTES`，可为 32、64、128 字节。

## 1. 连接端口

| 链路端口 | 当前类型 | 数据方向 | 存储侧应连接的端口 | 功能 |
|---|---|---|---|---|
| `mem_req` | `sc_fifo_out<SimpleMemRequest>` | 链路 → 存储 | `sc_fifo_in<SimpleMemRequest>` | 提交一整笔读/写突发；写请求包含全部写数据 |
| `mem_rsp` | `sc_fifo_in<SimpleMemResponse>` | 存储 → 链路 | `sc_fifo_out<SimpleMemResponse>` | 返回写完成状态，或完整读突发的数据与状态 |

两个端口分别连接一条有限容量 FIFO。成功写入请求 FIFO 表示接受排队，不表示操作完成；响应 FIFO 满时必须保留响应。这里没有额外的地址线、数据线或 valid/ready 信号，地址和数据都是 FIFO 对象中的字段。

`AouTarget` 自身有 `clk/rst_n`，但上述内存事务接口不包含独立的时钟/复位端口。当前简单内存通过 SystemC 等待时间推进；外部模型若需要 `tick()`，其周期和启动方式由适配层单独约定。

## 2. 当前请求字段：链路 → 存储

| 字段 | C++ 类型/单位 | 功能 | 对普通存储模型的处理建议 |
|---|---|---|---|
| `write` | `bool` | `true` 写，`false` 读 | 必需，映射为 `type` |
| `rp` | `uint8_t` | 资源平面，用于链路缓冲、额度与响应归属 | 存储模型不必接收，由适配器保留；单 RP 时为 0 |
| `address.id` | `uint16_t`，有效低 10 位 | AXI 事务 ID，可存在同 ID 多笔在途事务 | 适配器保存，另分配唯一 `request_id` |
| `address.addr` | `uint64_t`，字节地址 | 整笔突发首地址 | 必需，作为存储请求首地址；仅在需要拆分时计算子地址 |
| `address.len` | `uint8_t` | 拍数减一，实际拍数为 `len+1` | 保留为逻辑拍数；只需字节访问的后端可进一步换算总长度 |
| `address.size` | `uint8_t` | 每拍字节数的 log2，实际为 `1 << size` | 保留为每拍字节数，适配器据此转换字节 lane |
| `address.burst` | `uint8_t` | 当前只支持 INCR，值为 1 | 检查后可不传给只接连续字节访问的模型 |
| `address.lock` | `uint8_t` | 独占访问属性 | 普通读写后端不执行独占；适配器明确拒绝非零请求 |
| `address.cache` | `uint8_t`，协议有效 4 位 | 内存属性 | 当前简单内存不执行相关策略；普通字节后端可不接收 |
| `address.prot` | `uint8_t`，协议有效 3 位 | 保护属性 | 当前简单内存不做权限判断；需要保护检查时再扩展 |
| `address.qos` | `uint8_t`，协议有效 4 位 | QoS 属性，桥用其选择 RP | 普通存储模型可不接收；需要后端优先级调度时再映射 |
| `address.user` | `uint16_t` | 地址附加信息 | 适配器保存；沿用当前约定时回填到 B/R USER |
| `address.valid/ready` | `bool` | `AxChannel` 通用结构中的字段 | 不用于内存 FIFO 握手，精简接口不包含它们 |
| `write_beats` | `vector<SimpleMemWriteBeat>` | 整笔写突发的数据拍；读请求为空 | 写请求应含 `len+1` 项，适配器展开为连续字节 |
| `write_beats[n].data` | `array<uint8_t,D>` | 第 n 拍完整总线宽度的数据 | 提取该拍实际访问的 lane，放入 `payload` |
| `write_beats[n].strobe` | `array<uint8_t,D>` | 逐字节写使能，零禁用、非零启用 | 提取对应 lane，转换为 `byte_mask` |
| `write_beats[n].user` | `uint16_t` | 该写数据拍附加信息 | 当前简单内存不使用；当前普通读写对接可不传 |

`SimpleMemWriteBeat` 没有 LAST 字段：整笔数据长度已由 `len+1` 和向量项数确定。AXI 写拍的接收与 LAST 检查由上游完成。

## 3. 当前响应字段：存储 → 链路

| 字段 | C++ 类型/单位 | 功能 | 适配器如何生成 |
|---|---|---|---|
| `write` | `bool` | 区分写完成与读响应 | 从父请求上下文恢复 |
| `rp` | `uint8_t` | 返回到原资源平面 | 从父请求恢复；单 RP 时填 0 |
| `id` | `uint16_t`，有效低 10 位 | 返回原 AXI ID | 从父请求恢复，不能直接截断唯一请求编号 |
| `resp` | `uint8_t`，协议有效 2 位 | 写响应状态；读响应不使用本字段 | 汇总写子事务状态；成功 0，访问错误 2，地址错误 3 |
| `user` | `uint16_t` | 写响应附加信息 | 沿用当前约定时回填原地址 USER |
| `read_beats` | `vector<SimpleMemReadBeat>` | 整笔读数据；写响应为空 | 收齐读子事务后生成恰好 `len+1` 拍 |
| `read_beats[n].data` | `array<uint8_t,D>` | 第 n 拍完整总线宽度的读数据 | 按原地址和 SIZE 放回 lane，其余 lane 按当前约定填零 |
| `read_beats[n].resp` | `uint8_t`，协议有效 2 位 | 该读拍状态 | 按覆盖该拍的子事务状态生成 |
| `read_beats[n].user` | `uint16_t` | 该读拍附加信息 | 沿用当前约定时回填原地址 USER |

即使读发生错误，返回给当前 Target 的 `read_beats` 仍须有 `len+1` 项；错误拍提供确定的填充值和错误状态。写、读完成都不能静默丢失。

## 4. 按项目需求选择存储接口

```text
AouTarget ⇄ 现有请求/响应 FIFO ⇄ MemoryAdapter ⇄ 精简 Request/Response ⇄ 存储模型
```

接口应由本项目需要保留的行为决定。当前链路支持完整突发和窄访问，因此建议在项目存储边界保留逻辑拍数、每拍字节数；RP、原 AXI ID、USER 和总线 lane 布局由适配器维护。若具体后端仅接收连续字节访问，可在后端包装层进一步转换。

### 4.1 建议 Request：一笔请求表示一个完整 INCR 突发

| 字段 | 建议类型 | 功能 | 与当前接口的对应 |
|---|---|---|---|
| `type` | READ/WRITE 枚举 | 普通读写方向 | `write` |
| `request_id` | `uint64_t` | 本次存储请求的唯一标识，存活期内不复用 | 适配器分配，保存原 RP、AXI ID、方向及其他上下文 |
| `address` | `uint64_t` | 整笔突发首字节的系统物理地址 | `address.addr` |
| `beat_bytes` | `uint16_t` | 每拍访问的字节数 | `1 << address.size`，不一定等于总线字节数 |
| `beat_count` | `uint16_t` | 突发拍数，范围 1～256 | `address.len + 1`；不能用 8 位类型直接保存 256 |
| `payload` | `vector<uint8_t>` | 完整写载荷，读请求为空 | 按拍序、地址递增展开实际访问字节 |
| `byte_mask` | `vector<uint8_t>` | 与写载荷逐字节对应，0 禁用、非零启用 | 从对应 AXI lane 的 `strobe` 提取；读请求为空 |

当前接口限定按 SIZE 对齐、不跨 4KB 的 INCR，故不必为唯一支持的 burst 类型再增加动态字段；若扩展 FIXED/WRAP，应增加地址步进语义，不能继续按连续地址解释。该约束与当前桥一致。

总访问长度为 `beat_bytes × beat_count`，不必再存一份可能不一致的 `transfer_bytes`。写请求的 payload 和 byte_mask 长度均等于该乘积。`payload[i]` 对应 `address+i`；第 n 拍为数组中 `[n × beat_bytes, (n+1) × beat_bytes)` 的部分，不采用完整总线 lane 下标。若改用掩码位图，须明确位序和长度。

拍数和每拍字节数分别对应 AXI 的 `AxLEN+1` 和 `2^AxSIZE`，BURST 决定地址步进。[AXI 事务结构说明](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/IHI0022H_amba_axi_protocol_spec.pdf)

### 4.2 Response：存储模型 → 适配器

| 字段 | 建议类型 | 功能 |
|---|---|---|
| `request_id` | `uint64_t` | 关联原存储请求，方向和拍结构从上下文恢复 |
| `write_status` | 状态枚举 | 写请求的整笔完成状态；读响应不使用 |
| `read_status` | `vector<Status>` | 读请求每拍一个状态，项数等于 beat_count；写响应为空 |
| `payload` | `vector<uint8_t>` | 读请求完整数据，长度等于 beat_bytes × beat_count，错误拍填确定值；写响应为空 |

状态至少区分成功、地址错误和访问错误，由适配器映射 AXI RESP。逐拍读状态保留当前 `SimpleMemReadBeat.resp` 的表达能力；如果后端只报告整笔错误，由包装层按明确规则展开，不能宣称保留了它没有提供的错误粒度。

该响应仍然是整笔完成形式，不代表逐拍返回或每拍一个周期；不需要额外 LAST，因为拍数和向量长度已经表达边界。若要建模首拍到达即转发，须另行设计逐拍响应流、拍编号和背压，单纯增加 beat_count 不会实现这种时序。

### 4.3 只使用字节地址和总长度，能否表示 burst

对当前支持的普通对齐 INCR 访问，`address + transfer_bytes + payload + byte_mask` 可以表达整个访问范围及数据效果，但不能唯一保留原 burst 的拍结构。例如，16 拍 × 4B、8 拍 × 8B、2 拍 × 32B 都可能是 64B；仅看 transfer_bytes 无法区分。

如果存储模型只关心连续字节读写，字节接口是合理的，原拍结构保存在适配器中即可。如果存储模型的延迟、状态或调度要按原始拍计算，应保留第 4.1 节的 beat_bytes/beat_count。当前简单内存的服务时间包含每拍延迟项，删除拍结构后不能假定其时序行为仍相同。

### 4.4 父请求、子事务与 AXI beat 的区别

这里的父请求与子事务仅描述实现中的拆分关系。例如，一笔 256 位 AXI 的 4 拍全宽突发共 128B，若后端每次最多接受 64B，可以拆成两笔 64B 访问：原 128B 访问称为父请求，两笔 64B 访问称为子事务。每个子事务在该例中覆盖两个 AXI beat；子事务并不等于 beat。

不需要拆分时，一笔存储请求直接对应一笔突发，不必引入父子字段。发生拆分时，可在包装层维护：

```text
后端请求编号 → 原请求编号、字节偏移、长度、完成状态
```

每笔后端请求使用独立编号，包装层自行聚合结果，存储核心不必知道原请求共有几个子事务。`host_request_id + transaction_index + transaction_count` 只适用于明确要求后端参与分组处理的接口，不是普通存储接口的必需字段，也不是 AXI 的 LEN、ID 或 LAST 的替代物。

AXI 的 AWID/ARID 和 BID/RID 用于身份与顺序关联，但同一个 AXI ID 可以有多笔在途请求；它不等同于本节中每笔请求唯一的 request_id。当前 Target 没有向后端发送上述父子编号，只有完整突发及其方向、RP 和 AXI ID。

## 5. 哪些字段可以不对存储模型暴露

| 字段/机制 | 处理决定 | 限制 |
|---|---|---|
| RP | 精简接口不暴露，适配器保留 | 单 RP 配置填 0；多 RP 时恢复原值 |
| AXI ID | 精简接口不暴露原值 | 仍需唯一请求编号；不能取消事务关联 |
| LEN、SIZE、BURST | 建议保留逻辑 beat_count/beat_bytes，限定 INCR；纯字节后端可再转换 | 保留拍结构与只保留总长度的精度不同 |
| USER | 普通存储模型不接收 | 当前要求回送的地址 USER 由适配器保存，不能直接统一清零 |
| CACHE、PROT、QoS | 当前普通字节存储配置可不接收 | 不代表实现了权限、缓存或优先级语义；增加这些能力时需扩展 |
| LOCK | 不作为普通读写传给模型 | 非零请求必须拒绝，不能当普通访问执行 |
| valid/ready、LAST | 整笔事务对象不包含 | 接受/背压由 FIFO 或提交接口表达；拍数与数据长度表达边界 |
| 数据、掩码、长度、地址、完成状态 | 保留相应信息 | 普通数据读写正确性需要它们 |

**一份存储器不等于只能使用一个 RP。** RP 是链路内部的资源隔离通路，同一份内存可以承接多个 RP 的流量。若当前不研究这种隔离，桥与 Target 统一配置 `rp_count=1`，所有请求归 RP0，是合理的简化。

在精简后的存储模型接口里可以不要 `rp`；但若模型直接绑定当前 `SimpleMemRequest/Response`，该成员仍然存在，单 RP 时必须按 0 使用。当前 Target 用方向、RP、ID 匹配响应，因此不应仅删除结构成员而不修改消费逻辑。即使只启用 RP0，仍可能有多笔在途请求，事务编号和顺序处理不能省略。

## 6. 接线前需要确认的交互规则

| 项目 | 建议约定 |
|---|---|
| 接受与背压 | 有限 FIFO，或提交函数成功表示已接受、失败表示未接受且无副作用；失败后保留请求并重试 |
| 数据所有权 | 接受后模型复制数据或持有明确有效期的对象；调用方不能提前释放异步访问的数据 |
| 写完成 | 明确响应对应的时序阶段，并保证写完成后的依赖读能看到正确数据；入队不自动等于完成 |
| 响应背压 | 完成结果必须有有限暂存空间；不能因响应出口满而丢失 |
| 顺序 | 适配器按当前 Target 要求保持同方向、同 RP、同 AXI ID 的父请求完成顺序；重叠地址的数据依赖另行保证 |
| 地址与长度 | 确定物理地址窗口、容量、最大请求大小和对齐要求；地址减基址只能在明确的一处进行 |
| 非法访问 | 适配器提交任何写子事务前检查可预判的整笔范围/掩码错误；运行中后端错误的部分写副作用另行约定，不承诺自动回滚 |
| 时间与启动 | 确定 SystemC 调度或 tick 的周期、相位及启动顺序；仿真结束前排空请求与响应 |
| 数据初值 | 约定清零、镜像装载或其他初始化方式，并确认模型实际保存读写数据 |

首轮对接可固定 RP0，先验证单拍、突发、窄访问、部分写、读写错误和多笔在途；观察真实 AXI 握手及读回值。完整联仿及 trace 方案见[全链路联合仿真接入指南](全链路联合仿真接入指南.md)。
