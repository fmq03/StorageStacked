# 审计

审计回答“这个结果由什么输入和规则得到、验证到了什么程度、还能声明什么”，
不是迁移记录或发布历史。日常操作与测试入口见[项目指南](项目指南.md#tests)，
配置词典见[cfg指南](cfg指南.md)，结果有效性与指标口径见[输出指南](输出指南.md#validity)。

<a id="scope"></a>

## 1. 当前模型能够证明什么

本项目可以检查请求拆分、命令合法性、时序约束、数据/初始化/写掩码、
多 Stack 隔离、行为级 PHY 和统计结果的一致性。功耗、热、物理映射和链路开销
提供参数化研究模型，是否足以代表目标器件取决于校准证据。

下文的“数据读回检查”指先写入数据，再读取并与预期字节比较；trace 中的
`expect=HEX` 可明确指定预期读值。*golden* 是事先保存、供另一轮运行比对的参考数据，
不是厂家测量结果。没有实际执行比较时，错误数为 0 并不能证明数据正确。

必须区分三层结论：

| 层次 | 所需证据 | 不能替代的证据 |
|---|---|---|
| 实现正确性 | 单元/边界/序列测试、错误输入测试、写后读检查、回归 | 不能证明所有参数来自 JEDEC |
| 模型一致性与共同协议对照 | 同组织、单位、模式及负载下的独立重放和外部差分 | 外部开源仿真器不是真实芯片 |
| 器件级准确性 | 同一器件型号和工作条件下的厂商资料、厂商参考模型或硬件测量，以及误差报告 | 配置标签、严格模式通过和漂亮曲线均不能代替 |

“能运行”“没有 mismatch”“validator pass”和“厂商级准确”不是同义词。
不将研究默认值、由研究值推导的量或未实际执行的检查包装成已校准证据。

## 2. 来源与适用条件

| 来源标签 | 应有的依据 | 主要限制 |
|---|---|---|
| jedec | 可定位的标准版本、表/条款、单位和模式条件 | 标准可能只定义含义/边界，不给所有器件数值 |
| vendor | 具体料号、资料修订、表项和 operating point | 不能混合不同速度、温度、密度或模式的参数 |
| external_reference | 外部仿真器版本、实现文件、组织与 Timing 配置 | 代表外部模型选择，不等于厂家实现 |
| derived | 公式、输入与取整规则 | 可信度不能高于所依赖的输入 |
| research_default | 为探索选定的默认/假设值 | 需要敏感性实验，不对真实器件作准确性承诺 |

当前没有明确来源的 Timing 覆盖默认是 research_default；
分段 source/reference 按该段绑定，不依赖它写在同段数值之前还是之后。
配置格式、联动及可用键见 cfg 指南；此处只规定证据要求。
timing_profile/vendor_profile/mode_profile 名称是身份记录，不会凭名称自动产生正确数值。

### 2.1 Timing 审计检查点

逐项核对有效 Timing 表，而非只检查配置文本：

1. 所选协议/组织/速度是否与预期一致，ns↔nCK 的 tCK 和取整是否正确。
2. same/different BG、PC、SID、bank/rank 的适用范围是否正确。
3. 最小等待与最大 deadline 是否分开；不能把最大值当最小值。
4. 密度、温度、刷新模式、RL/WL、WCK 比例等是否属于同一合法组合。
5. 派生值是否记录了依据，显式覆盖是否有有效来源；空 reference 需要补证据，而非补随意文字。

HBM 的跨 SID nCCDR 不能套成所有列命令间隔；LPDDR 分拆 ACT 的第二阶段既要
避免过早，也要避免超过 deadline。相应实现与测试是否满足标准，必须由具体序列验证。

### 2.2 strict 检查的边界

--strict-timing-table 是程序对数值/来源元数据门槛的检查。
它不会验证 source=vendor 所指文档是否真实存在、页码是否正确、
不同表项是否属于同一器件工作点，也不会认证 PHY 训练、IDD、热参数和 ECC 的真实性。
因此 strict 通过只是审计的一项输入；不能通过给研究值换标签获得器件级资格。

## 3. 参考资料登记

本项目使用 JEDEC 规范定义的接口和命令语义，并以 Ramulator2、DRAMsim3 的
共同支持面作辅助对照。具体版本和参数应随实验产物保存，不用外部项目的名称替代参数证据。

用户提供的参考文献包括：

| 资料 | 使用范围与登记要求 |
|---|---|
| HBM4 JESD270-4A.pdf（另有双语辅助版） | HBM4 组织、命令和 AC Timing；引用英文原文的标准条款/表号 |
| jedec JESD209-6：2025 LPDDR6 Standard ）.pdf（另有双语辅助版） | LPDDR6 命令、工作模式与 Timing；引用英文原文 |
| DDR_PHY_Interface_Specification_v6.0.1.pdf | 接口名称和行为契约参考；不声明本项目完整实现全部 DFI 端口 |
| Ramulator2 本地源码 | 保存 commit、标准实现、组织表、时序表、调度器和运行配置 |
| DRAMsim3 源码与参数 | 仅选择双方共同支持的协议/公式，记录其参数与单位 |
| 目标器件 datasheet / 厂商模型 | 记录料号、版本、速度、密度、温度、模式及完整出处 |

双语文件的译文用于辅助阅读，不作为替代英文条款的数值证据。
目录中列出某张表，不证明提供的 PDF 实际包含该表正文；缺页或缺器件表时保持
research_default/vendor_required 的诚实声明，不从现有代码常量反推成标准值。
本仓库的参考清单不要求把受许可限制的资料上传或公开。

参考元数据入口包括 [configs/profile_index.csv](../configs/profile_index.csv)
和 [configs/validation](../configs/validation/README.md)；
实际生效参数始终以同次运行 resolved.cfg 与 timing.csv 为准。
索引数值列描述执行模型，`reference_model` 描述参考端身份；共同命令面中的缩减或
扩展几何不能借参考型号名称被解释为完整器件容量一致。
本指南不另维护一套重复的默认 Timing 数值表。

## 4. 验证层次与证据链

| 方法 | 应观察的证据 | 常见误读 |
|---|---|---|
| 配置检查 | 合法组合接受、错误/矛盾组合拒绝；resolved 可重载 | 解析成功不等于标准器件合法 |
| Timing 边界 | 其他条件满足时，最小间隔 t−1 拒绝、t 允许；deadline 另测最后合法点与超期点 | t 时仍可能被另一条约束阻塞 |
| 命令序列测试 | ACT/读写/PRE、刷新/RFM、低功耗和数据完成状态 | 一个 stream 冒烟不能覆盖所有转换 |
| 独立命令重放 | 使用完整 trace 重新检查状态、Timing、tFAW、WCK 等 | 执行侧自己返回 pass 不是独立证据 |
| DFI 检查 | 命令与数据事件关联、顺序、beat、mask 和模式契约 | 抽象 DFI 自洽不等于电气/训练合规 |
| 数据读回检查 | 用 `expect=` 比较读值，并检查写掩码、未初始化数据、转发合并与 ECC | 错误数为零但没有执行读值检查，不算独立数据验证 |
| 多 Stack / 后端差分 | 相同输入的实例隔离、最终数据及初始化一致、重开行为 | 宿主文件大小不等于模拟容量 |
| 热节点契约 | 先耦合后直接受热仍保留预热、冷却/事件增量、邻居自身坐标与未知地址标记 | 温度图能显示不等于热状态更新正确；契约通过不证明材料模型准确 |
| 外部共同协议差分 | 同组织/事务/Timing/维护/调度边界下的可解释差异 | 不同默认参数下的吞吐差异不能直接判 bug |
| 性能扫描 | 有效点、饱和趋势、队列和延迟变化 | 自洽曲线不等于真实芯片性能 |
| 敏感性/不确定性 | 参数范围、采样方案和输出区间 | 随意假设的区间不是厂商精度保证 |

默认测试目标的包含关系只在项目指南维护。审计应引用实际日志与输入，不在文档中
写死“通过了多少行边界”“固定某个 cycle 数”，以免把样例当作每次运行的结果。

### 4.1 Ramulator2 与 DRAMsim3 的定位

Ramulator2 是共同命令面的外部参考，不是本项目实现的最终裁决者。
差分前需对齐 channel/PC/SID/bank/row/column、事务宽度、CK/tick、
速率、刷新、行政策、调度、请求到达顺序与完成统计口径。
单通道 validation 配置就是为了缩小到可比范围，不表示完整器件只有一个 Channel。

发现差异时依次检查配置、单位、范围、调度决策、完成定义，最后定位模型实现。
本项目独有的数据后端、Host 重组、热映射或 PHY 功能，不应要求外部工具产生不存在的字段。

外部差分报告还应记录 external_engine_executed、外部可执行文件、Git commit/dirty 状态
和双方原始产物。仅运行一个名称含 ramulator 的本项目配置，不代表实际执行了外部引擎；
参考端未实现的特性应标为 unsupported，不为追求数值相同而删去差异。

### 4.2 重点场景与适用边界

以下是当前模型需要特别核对的场景。表中“检查方式”指应运行的测试或核对的产物，
不是声称某次实验已经通过；实际结论仍以本次日志为准。

| 场景 | 检查方式 | 不能据此声称什么 |
|---|---|---|
| LPDDR6 BL24 与列间隔 | 查看生效 Timing 表，并运行速度分档及读写换向边界测试 | 未覆盖的 BL48 或超出表格速率档不能按标准值宣称 |
| LPDDR6 双 Bank 刷新 `REFdb` | 检查短/长间隔、Bank 对轮转以及发令轨迹；运行序列和时序边界测试 | 当前固定相邻 Bank Group 配对；其他组织需要重新验证 |
| LPDDR 验证地址单位 | 核对验证配置的列数换算、容量及首末地址 | 单通道对照不代表完整器件容量或完整字节映射相同 |
| DRAMsim3 辅助对照 | 核对双方实际使用的旧协议共同组织、命令和能量参数 | 不能把旧协议结果当作 HBM4/LPDDR6 协议验证 |
| 地址边界及数据 | 检查首末地址的写后读，以及恰好越界的拒绝行为 | 少数边界用例不能代替大规模随机数据测试 |
| 接口附加位与 ECC | 分别检查有效数据、配置的附加位需求和数据层 ECC | 当前没有逐引脚数据装载模型；附加位不能无条件折算成固定额外字节 |
| DFI 导出 | 核对抽象事件及启用的检查数 | CSV 中项目自定义字段不等于同名规范端口或 DFI 认证 |

外部对照必须保存参考软件版本、构建选项、双方配置和原始报告。参考仓库若有本地改动，
还应保存改动内容；仅记录 commit 不能说明使用的是未修改的上游版本。

## 5. 需要厂商补齐或单独校准的部分

| 类别 | 校准输入 | 验证方式 |
|---|---|---|
| RL/WL、行列时序 | 目标速度/温度/密度/模式表、边界与取整 | 表项复核 + 对应命令边界序列 |
| refresh/RFM | 刷新时长、间隔、温度档、bank-pair、RAA/PRAC 门限和递减 | 维护序列、阻塞范围和性能影响 |
| PHY 初始化/训练 | reset/init/training、重训练/退出及频率切换流程 | 厂商事件或硬件对照；当前是行为延迟 |
| WCK、DQS、链路保护 | 模式和时序、有效载荷损耗、校验/重试规则 | 协议事件与有效数据率核对 |
| ECC/RAS | 编码、保护粒度、纠错能力、scrub/repair 行为 | 明确故障模型下的注错与响应 |
| IDD/功耗 | VDD、各状态电流、工作点、活动假设 | 同负载能量分解及测量误差 |
| 热与封装 | 材料/边界条件、热容/热阻、TSV、真实尺寸和环境 | 瞬态/稳态对照，不只看峰值 |
| 组织与地址映射 | 料号容量、逻辑层级、die/channel 物理关系 | 几何容量、地址覆盖及物理映射验证 |

HBM 的 SID 寻址层级不等于单颗 die。LPDDR 的密度归一口径也不能直接套 HBM stack_height。
计算公式与自动联动见 cfg 指南；热坐标目前的 Channel 聚合等限制见项目指南，
不得在报告中称为完整厂商 floorplan。

## 6. 一次可追溯实验应保留什么

保留模型源码/构建身份、输入配置和 resolved 快照、Timing 表及来源、
trace 或合成负载/seed/地址域、result JSON、所启用的检查报告；
若做外部差分，另存参考版本和对齐配置。

报告最少回答：

- 模拟哪个基础协议和研究模型，哪些输入有意偏离基准？
- 哪些检查真正执行，是否正常完成，是否仍有待处理事务或错误？
- 外部参考覆盖哪些范围，差异如何解释？
- 哪些输入仍是假设，结论对它们有多敏感？
- 最终结论是“实现自洽”“共同协议对照一致”还是“器件级校准”？

这些是实验依据，不是要求把开发迁移过程写入交付手册。数值含义和性能分析只引用输出指南，
避免另建一份同名指标表。
