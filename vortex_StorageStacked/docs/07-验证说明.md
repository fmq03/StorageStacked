# Vortex 验证说明

[返回文档目录](README.md)。本文集中保存原历史验证目录中的执行方法、结果和适用范围。
以下分别记录历史矩阵和本轮离线 Docker 专项的已完成结果。

## 验证方法

从仓库根目录执行 `SS_OFFLINE=1 ./build.sh --test`，默认 SMOKE、TinyLLM 各执行一次，
并检查配置、19 项原生存储测试、在线 C ABI、独立数值、CPU 实际执行及错误拒绝。
单个项目可执行 `./user/run.sh smoke --test` 或 `./user/run.sh llm --test`。
通过还要求主机 ELF 架构、GPU 线程工作量及 AXI/VCD/Flit/在线内存真实回读字节一致。
编译成功或设备退出不等于总结果 `summary.json.passed=true`。

## 离线 Docker ARM 专项：2026-10-22

镜像运行源码冻结在 `fea18107`。AArch64 SMOKE 使用 4 个主机 CPU，GPU L1I/L1D 为
2 路、3 周期，L2 开启、8 路、6 周期。实际输出 `42`，4 个 CPU 均执行了任务；
2,305 笔存储事务通过计算、AXI/VCD、Flit 和在线内存检查，内存检查错误为 0。

本轮发现 Ubuntu 20.04 AArch64 glibc 的 `memcpy` 会向不可缓存设备 BAR 发出 `PRFM`，
项目的 ARM SE 直接页表路径遗漏了对应检查，导致原运行达到 `max_ticks`。
修复沿用 gem5 全系统路径的 `PrefetchUncacheable`，CPU 撤销设备预取，普通读写继续经过真实链路。
同一 SMOKE 复跑通过，并实际记录 5 次设备预取拒绝；离线验收要求该计数大于 0。

此项属于离线镜像中的 ARM SMOKE 专项；三项目归档导入和完整回归见
[离线包验收说明](../../offline/VALIDATION.md)。

## SIMT 与数值：2026-10-08

批次 `test-20261008-173856` 完整回归通过，19 项原生测试、在线接口及 29 项错误拒绝检查通过。
默认 SMOKE=42、863 周期；TinyLLM=blu、225771 周期。
当次 TinyLLM 的一个工作组实际在 GPU 核 0 使用 8 个线程、2 个 warp，完成 42 次线性层调用，
每线程实际输出列数为 `[60,54,54,54,54,54,54,54]`。
线性层按列分工，其他阶段由线程 0 执行，阶段间使用屏障。
权重、KV、中间值、token 和线程工作量独立核对；最大中间值绝对误差约 `3.42e-6`，
在当次容限内。配置容量与实际使用的核/线程数分别记录。

## 错误拒绝、历史修正及范围

检查覆盖空闲 CPU、缺失/重复线程、错误列分工、错误 ELF ISA、非法配置、
损坏权重/KV/中间值/token、错误回读和缺失输出。
早期 ARM TinyLLM 因 gem5 警告插入长回读行而验收失败；改为独立保存主机输出、结束后追加日志，
最终四个 ISA 场景通过，失败尝试未计入成功结果。

原历史验证目录已退出项目树，关键结论保存在本文；用户结果和内部回归缓存继续由运行器维护。
公共 AXI 验证见 [输出与验证说明](../../axi_StorageStacked/docs/OUTPUTS.md)。
2026-10-22 工作区编辑器验证还完成 3457 次定义跳转且零失败；导航检查不代替功能仿真。
本文结论属于 gem5 + Vortex SimX 指定负载，不包含 GPU RTL 综合、FPGA/芯片实现、
完整大模型精度或所有缓存组合的性能保证。
